## Check 2 — labelling: the assumption FAILED

The plan set `grid = parts[0]` and `cell = parts[1]`. Against a real Hydra tree
that produced:

```
2026-07-24/alpha_sweep/joint_pareto/… -> grid='2026-07-24' | cell='alpha_sweep'
```

Every grid was a **date**. Hydra's default layout is
`outputs/<date>/<experiment>/…/<time>`, so position 0 carries no experimental
meaning. This was not merely inaccurate — it violated the spec's central
invariant, that the Python layer never infers repository semantics. A positional
guess is exactly such an inference.

**The rule that is correct**, now implemented: the package labels nothing unless
the repository declares how. `.mlragents.toml` gains `paths.run_pattern`, one
pattern or an ordered list, where `{name}` captures a component, `*` skips one,
`**` skips any number and must be last. A pattern that does not match yields no
labels, because a wrong label is worse than an absent one.

A single pattern was still not enough. With `*/{grid}/{cell}/**`, the 55
depth-3 runs (`<date>/<experiment>/<time>`) had their **timestamp recorded as a
cell** — 35 of them. Those runs genuinely have no cell. Hence the ordered list:
the shallow, exact-arity pattern is tried first.

SURF_2026's adapter (`examples/surf-2026.mlragents.toml`):

```toml
run_pattern = ["*/{grid}/*", "*/{grid}/{cell}/**"]
```

Re-run after the change:

```
total runs: 823
labelled with a grid: 823
cells that are really timestamps: 0
grids that are really dates: 0
top grids: sheared_swap_mirrored_pareto_ablation_eval (84), alpha_sweep (77),
           sheared_swap_gaussian_ablation_eval (61), …
```

The recovered grid names match the ablation families the repository actually
uses, so the labels are now the experiment's own vocabulary rather than the
filesystem's.

## Check 3 — the live cluster path

| | hand-run | via package |
|---|---|---|
| `squeue` rows | 1 | 1 |
| `sacct` rows (7 days) | 2 | 2 |

Held; the pinned format strings parse real output exactly.

**One defect found.** `sacct` prints `0:0` in the ExitCode column for a job that
has not finished, so a RUNNING job was reported as `exit_code='0:0'` — readable
as a clean success. An agent asked "did my run succeed" could have been told yes
about a job still executing. `_parse` now clears the exit code for any
unfinished state (`RUNNING`, `PENDING`, `SUSPENDED`, `REQUEUED`, `RESIZING`).
Verified live: job 2541417 (RUNNING) now reports `exit_code=None`, while the
finished TIMEOUT job retains `0:0`.

## Consequences

- `paths.run_pattern` is part of the adapter contract; `docs/mlragents-toml.md`
  documents it.
- Repositories that declare no pattern get unlabelled runs. That is the intended
  default, not a degraded mode.
- Both defects found here were of the same kind: code that quietly produced a
  plausible-but-wrong fact. Neither would have surfaced against a fixture.
